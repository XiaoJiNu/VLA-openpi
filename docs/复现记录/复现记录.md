# openpi 最小模型本地推理复现记录

## 前置条件
- 系统：Ubuntu 22.04（官方验证环境）；需安装 NVIDIA 驱动和 CUDA Runtime。
- GPU：≥ 8 GB 显存（推荐选择 `π0-FAST` 系列，参数量更小，更易在 8 GB GPU 上成功推理）。
- Python 环境：使用项目默认的 `uv` 管理依赖，避免手动 pip 版本冲突。
- 网络：可访问 `gs://openpi-assets`（项目默认使用 `fsspec` 直连 GCS，国内可能需要梯子或代理）。

> 提示：当显存紧张时，可在运行推理前设置
> `export XLA_PYTHON_CLIENT_PREALLOCATE=false` 和 `export XLA_PYTHON_CLIENT_MEM_FRACTION=0.7`
> 让 JAX 只按需申请显存。

## 环境搭建步骤
1. **初始化代码仓库**（首次克隆需要同步子模块）：
   ```bash
   git clone --recurse-submodules <this-repo-url>
   cd VLA-openpi
   ```
2. **安装依赖（使用 uv）**：
   ```bash
   GIT_LFS_SKIP_SMUDGE=1 uv sync
   GIT_LFS_SKIP_SMUDGE=1 uv pip install -e .
   ```
   - `GIT_LFS_SKIP_SMUDGE=1` 避免首次同步时自动拉取 LeRobot 等大型 LFS 文件。
   - 若需要 CPU 环境测试，可另外安装 `jax[cuda==12]` 对应版本；项目 `uv.lock` 已锁定兼容版本。

3. **检查 GPU 是否就绪（可选）**：
   ```bash
   nvidia-smi
   ```

## 下载最小推理模型
- 推荐使用 DROID 平台的 `π0-FAST` 推理模型（动作维度更小，显存压力最低）：
  - 训练配置名：`pi0_fast_droid`
  - Checkpoint：`gs://openpi-assets/checkpoints/pi0_fast_droid`
- 项目内置的 `openpi.shared.download.maybe_download` 会自动把远端权重缓存到 `~/.cache/openpi/openpi-assets/...`。

如需提前手动下载，可运行：
```bash
uv run python -c "from openpi.shared import download; download.maybe_download('gs://openpi-assets/checkpoints/pi0_fast_droid')"
```

## 推理脚本示例
使用项目 API 直接在本地加载模型并执行一次推理：
```bash
uv run python - <<'PY'
from openpi.training import config as _config
from openpi.policies import policy_config
from openpi.policies import droid_policy

# 1. 加载最小配置与权重
config = _config.get_config("pi0_fast_droid")
checkpoint_dir = "gs://openpi-assets/checkpoints/pi0_fast_droid"
policy = policy_config.create_trained_policy(config, checkpoint_dir)

# 2. 构造示例观测（真实场景请替换为传感器数据）
example = droid_policy.make_droid_example()
result = policy.infer(example)

print("动作张量形状:", result["actions"].shape)
print("前两帧动作:", result["actions"][:2])
PY
```

脚本说明：
- `create_trained_policy` 会自动处理权重下载、归一化统计加载以及输入输出变换。
- `droid_policy.make_droid_example()` 生成的假数据包含：
  - `224×224` 的 base 摄像头图像、手腕图像（`uint8` 格式）；
  - 7 维关节角与 1 维夹爪位置；
  - 文本指令字符串。
- 若替换真实数据，确保：
  - 图像转为 `uint8` 且为 `H×W×C`；
  - 关节与夹爪拼接后的状态向量长度符合模型配置（`pi0_fast_droid` 为 8 维）；
  - `prompt` 使用 UTF-8 文本。

推理输出 `result["actions"]` 为 `(action_horizon, action_dim)`（默认 `10×8`）的动作块，可在机器人控制循环中按需执行。

## 在机器人或自定义环境中接入
1. 将真实传感器读数映射为示例字典同名键值。
2. 频率较高的推理建议复用同一个 `policy` 实例，避免重复加载权重。
3. 若需要远程部署，可用 `uv run scripts/serve_policy.py --env DROID` 启动 websocket 服务端，再于机器人侧使用 `packages/openpi-client` 发送观测。

## 常见问题排查
- **显存不足**：
  - 确认已使用 `π0-FAST` 模型；
  - 设置 `XLA_PYTHON_CLIENT_PREALLOCATE=false` 后重试；
  - 尝试关闭无关 GPU 进程，或在 `policy_config.create_trained_policy` 时传入 `pytorch_device="cpu"` 强制走 CPU（速度慢，但可验证流程）。
- **无法下载模型**：
  - 检查网络/代理，确保能访问 `storage.googleapis.com`；
  - 也可提前通过其他机器下载后复制到本地 `~/.cache/openpi`。
- **输入尺寸不匹配**：
  - 使用项目提供的 `openpi.transforms` 辅助函数进行归一化；
  - `droid_policy.DroidInputs` 可作为将原始数据映射到模型输入的参考实现。

按照以上步骤，即可在本地 8 GB GPU 环境下复现 openpi 最小模型的推理流程。
